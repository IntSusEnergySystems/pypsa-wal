# Common parameters: TIMES/PyPSA shared assumptions

`config/input_parameters_for_models.csv` is the negotiated list of assumptions that are
**not** soft-linked but that TIMES-WAL and PyPSA-WAL are supposed to share: technology
costs and lifetimes, fuel prices, regional RES potentials, the CO₂ trajectory,
interconnection capacities, transport-flexibility settings and the TIMES-side activity
drivers.

**Status (2026-07-26):** currency rebase to **EUR2025** is done (§4), including HICP
inflation of EUR2023 literature/TIMES prices and Valbiom EUR2020 CAPEX (§8.8–8.9).
Modeller decisions §8.1–8.7 are in `pypsa_wal_target` / `year_rule` / `status`.
Artefact `--write` is **not** done yet.

```
shared CSV (monetary values in EUR2025; year in the unit)   ← DONE for currency
        │
        ├─► TIMES-WAL  (EUR2025; TIMES-only prices rebased by TIMES team)
        └─► pypsa-wal  (CSV → custom_costs override; else technology-data fallback)
                         ↑ artefact generation NOT wired yet
```

## 4. Currency-year strategy (decided + executed)

### 4.1 Rules (unchanged)

1. **Project reference year = EUR2025.**
2. Currency year is part of the unit (`EUR2025/kW_e`, …). `year_currency` must match.
3. **Non-PyPSA rows** (`Revue de littérature`, `TIMES`): treat as already EUR2025 — retag only.
4. **PyPSA-origin rows**: refresh from the archive pin in `config/common_parameters_meta.yaml`.
5. **CSV is authoritative** over pypsa-wal once artefact generation is wired.

### 4.2 Name mapping

| `technology_name_pypsa` | key in `costs_<year>.csv` |
|---|---|
| `solar utility` | `solar-utility` |
| `solar rooftop` | `solar-rooftop` |
| `Nuclear (advanced)` | `nuclear` |
| `Eletricity distribution grid` | `electricity distribution grid` |
| `Battery storage (utility)` | `battery storage` |
| `e-methane` | `methanation` |
| `Uranium cost` | `nuclear` (CSV `price` → cost-file `fuel`) |
| `OCGT hydrogen` / `CCGT hydrogen` | **skip** |
| `Nuclear (SMR)` | **skip** (SMR = steam methane reforming in cost file) |
| `carbon sequestration` | **skip** |
| empty `technology_name_pypsa` | **skip** (CCGT/OCGT with capture placeholders) |
| *(exact match otherwise)* | same string |

### 4.3 Executed — refresh PyPSA monetary rows (2026-07-26)

**Inputs:** `config/input_parameters_for_models.csv`,
`data/costs/archive/v0.14.0/costs_{2030,2040,2050}.csv`,
`config/common_parameters_meta.yaml`.

**Script:** `scripts/refresh_common_parameters_currency.py`
(re-runnable; `--dry-run` available).

| metric | count |
|---|---:|
| candidates (`data_origin_choice=PyPSA`, units contain EUR, year ∈ 2030/40/50) | 136 |
| updated | **121** |
| skipped | **15** |
| errors | **0** |

Skipped: CCGT/OCGT hydrogen ×3, carbon sequestration ×3, empty-name capture plants ×6.

Checks passed: `year_currency=2025`, units start with `EUR2025`, no NaN values, spot-check
equality vs archive (≥4 sig figs) for CCGT/OCGT/electrolysis/HVDC inverter pair investment
and onwind VOM. Audit columns cleared.

**Pin verification (2026-07-26):** upstream latest is **v0.15.0** (still `eur_year=2025`).
Core CAPEX and fossil prices are unchanged vs v0.14.0; #275 only fixes the `currency_year`
*metadata* column. Local archive files are byte-identical to published v0.14.0.
**Decision: stay on v0.14.0** for this rebase. Ignore v0.14.0’s `currency_year` column when
tagging units (it is still the DEA source year). Do not use `v0.14.0-2020*` tags.
Runtime retrieve pin remains `data/versions.csv` → v0.14.0 (independent of a later bump).

**Forbidden (still):** hand-multiplying by 1.26; using processed cost files; touching
non-PyPSA values; inventing keys not in §4.2.

### 4.4 Executed — retag non-PyPSA monetary rows (2026-07-26)

**33 rows** retagged (`year_currency=2025`, `EUR`→`EUR2025` in units). **Values unchanged.**
Includes Valbiom rows formerly tagged 2020 and TIMES/CLIMA fuel prices formerly tagged 2023.

**Source-vintage audit (2026-07-26)** against CSV notes and the Climact consultation deck
(21 Oct 2025). §4.4’s blanket retag was intentional, but purchasing-power fidelity varies:

| group | documented vintage | action (2026-07-26) |
|---|---|---|
| Nuclear (advanced / SMR), onwind (Edora “CAPEX 2025 ≈ 1450”) | ~2025 consultation | retag-only OK |
| solar utility / rooftop (IEA PVPS; consultation €2023) | EUR2023 | **inflated** ×1.051650 → EUR2025 |
| H₂ import (EnergyVille PATHS; was year_currency 2023) | EUR2023 | **inflated** ×1.051650 (status=none still) |
| coal / gas / oil (CLIMA.A; tagged 2023) | EUR2023 | **inflated** ×1.051650 |
| biogas / biogas upgrading (Valbiom; was year_currency=2020) | EUR2020 | **inflated** ×1.257335 → EUR2025 |

Factors = Eurostat HICP EEA annual rates, same method as technology-data v0.14.0
(`prepare_inflation_rate` / `adjust_for_inflation`). Each inflated row’s
`note_complementaire` starts with `INFLATED 2026-07-26:` (old value, factor, new value).
See `config/common_parameters_meta.yaml` → `hicp_inflation`.

## 8. Modeller decisions

### Decided (2026-07-26)

1. **CO₂ trajectory** — use the CSV anchors (64.8 % / 45 % / 5 % on 2030 / 2040 / 2050).
   `year_rule=interp`: extra planning horizons (2025, 2035, …) interpolate between anchors.
   Target `config:budget_national` (store as fraction = value/100). **status=active**
2. **Nuclear SMR** — clearly distinguished from steam methane reforming. Nuclear (SMR) is
   **status=none** (`none:nuclear_smr_not_in_pypsa_wal`) with a permanent WARNING note.
   Never write those costs onto cost-file key `SMR`. `SMR CC` annotated as steam-methane+CC.
   When `--write` runs, strip erroneous `SMR` investment/lifetime rows from custom_costs.
3. **Potentials** — CSV authoritative (e.g. biogas 8300, solid biomass 6000, non-zero
   non-EU pellet imports). Supersedes `custom_potentials_corrige.csv`. Waste heat / deep
   geothermal kept as **status=none** (not applied in pypsa-wal). Walloon-only rows missing
   from the CSV were added with notes: `CCGT p_nom_min`, `nuclear p_nom_max (BE nodes)`.
4. **Discount rate** — CSV keeps 4 % as the agreed figure (**status=pending**). Until a
   dedicated discount-rate task, pypsa-wal may keep 7 % / 2 % social / 4 % rooftop. Do not
   overwrite from this row yet.
5. **Lifetimes** — CSV authoritative. Where Walloon `custom_costs` had a *different* value,
   the CSV value wins and a note records the superseded Walloon figure. Where Walloon had a
   lifetime **absent** from the CSV, it was **added** (nuclear retrofit, solar, rooftop
   commercial/residential, solar-utility single-axis tracking, biogas, biogas upgrading,
   e-methane, CO2 storage tank; Nuclear (SMR) lifetime documented at status=none only).
   Follow-up from the gap audit: also added missing non-lifetime Walloon overrides —
   `nuclear retrofit` investment/FOM/efficiency, and `solar-utility single-axis tracking`
   investment trajectory. Scenario-only nuclear CAPEX (11500 / 13500 in
   `custom_costs_nuc*.csv`) stays out of the master CSV for §5.7 scenario deltas.
6. **H₂ imports** — **no imports from the rest of the world** (**status=none**). Exchange
   among simulated countries remains allowed. Do not enable `sector.imports` for extra-EU H2.
7. **Empty EUR placeholders** — left in place (**status=pending**) with a “further refined”
   note (H2 turbines, gas+capture, sequestration, …).

Script that applied targets/notes/additions: `scripts/apply_common_parameters_decisions.py`
(re-run only with care — it is not fully idempotent for appended rows).
